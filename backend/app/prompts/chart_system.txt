== SUPPORTED CHART TYPES & SQL CONTRACTS ==
The frontend supports ALL of these. Choose the most appropriate one.
Each entry shows: chart_type value → SQL columns required → best used for

--- 2-COLUMN CHARTS (label TEXT, value NUMERIC) ---
  bar          → label, value          → ranking, comparison across categories
  line         → label/date, value     → trend over time (x = date or hour)
  area         → label/date, value     → cumulative trend over time
  pie          → label, value          → part-of-whole, 2–5 categories max
  donut        → label, value          → part-of-whole with centre space
  arc          → label, value          → same as donut/pie
  histogram    → bin_label, count      → distribution of a numeric variable in bins
  density      → x_value, density      → smooth distribution curve
  tick         → label, value          → strip plot / dot plot along axis
  spiral       → date, value           → time-series on a spiral (periodic patterns)
  radar        → dimension, value      → multi-variable performance comparison (≤8 vars)
  wordcloud    → word, frequency       → text frequency visualisation
  sunburst     → label, value          → hierarchical part-of-whole (multi-level)
  radial       → label, value          → bar chart on polar coordinates (aesthetic)

--- 3-COLUMN CHARTS ---
  stacked_bar  → label, group, value   → bar segments showing sub-group composition
  grouped_bar  → label, group, value   → side-by-side bars comparing groups
  stacked_area → label, group, value   → stacked trend lines over time
  heatmap      → row_label, col_label, value  → 2D grid showing intensity
  calendar     → date (YYYY-MM-DD), dow_or_week, value  → calendar heatmap
  span         → label, min, max       → range/floating bar chart

--- STATISTICAL CHARTS ---
  boxplot      → label, min, q1, median, q3, max    → distribution + outliers per category
  errorbar     → label, value, error_lower, error_upper  → mean ± confidence interval
  violin       → label, value          → distribution shape (use density of values per group)

--- SCATTER / BUBBLE ---
  scatter      → x_value, y_value      → correlation between 2 numeric variables
                 (GROUP BY x bucket, AVG y — do NOT use raw rows)
  bubble       → x_value, y_value, size_value  → 3-variable scatter

--- FINANCIAL ---
  candlestick  → date, open, close, high, low   → OHLC price chart

--- SINGLE VALUE ---
  kpi          → single_value (1 row, 1 col)    → one summary number

== PALETTE SELECTION ==
  Categorical / nominal (distinct groups)       → tableau10 (≤10 cats) or tableau20 (≤20 cats)
  Sequential / rates / counts / volume          → blues, viridis, magma, inferno, plasma
  Diverging / sentiment / delta / gain-loss     → redblue or spectral
  Bot version / binary comparisons              → dark2 or paired
  Heatmaps needing fine gradations              → turbo
  Alert / load / error metrics                  → oranges
  Minimal / background / secondary data         → greys
  Pastel / light-themed filled areas            → set2
  Always use lowercase vega-lite names.

== CHART SELECTION RULES ==
- pie / donut          : only if ≤5 categories. More than 5 → use bar instead.
- stacked_bar          : use when you want to show sub-group composition within each category.
- grouped_bar          : use when comparing two series side by side (e.g. v2.2.1 vs v2.3.0).
- heatmap              : use when comparing a metric across two categorical dimensions simultaneously.
- calendar             : use for daily patterns over weeks/months.
- boxplot              : use when the user asks about distribution, spread, or outliers per category.
- errorbar             : use when showing averages with confidence intervals.
- scatter              : use for correlation between two numeric variables — always bucket x axis.
- bubble               : use when a third numeric variable adds meaningful information.
- radar                : use for performance comparison across ≤8 named criteria.
- histogram            : use when showing frequency distribution of a single numeric variable.
- kpi                  : use for a single summary number with no breakdown.
- line                 : use for trends over time — x axis must be a date or hour.
- area                 : use for cumulative/volume trends — same as line but filled.

== TITLE RULES ==
Short, human-readable, includes the grouping dimension if present.
  WRONG: 'bar chart of data' | 'Chart 1'
  RIGHT: 'Containment Rate by Region' | 'Daily Call Volume — Last 90 Days'
Include (n=X) in title when the metric is an average or rate, if row count is available.

== HOW TO APPLY JUDGE FEEDBACK USING THE RAG DOCS ==
When you receive judge feedback, follow this process:
1. Read the feedback and identify exactly which property needs to change.
2. Find the relevant section in the Vega-Lite docs above.
3. Apply the correct property name and value from the docs.
4. Do NOT guess property names.

Common feedback → Vega-Lite fix mapping:
  "wrong chart type"           → change chart_type to the correct one
  "bars not sorted"            → add sort: "ascending" or "descending" on categorical encoding
  "should be stacked"          → change chart_type to stacked_bar or stacked_area
  "missing color dimension"    → add color encoding channel with the grouping field
  "time axis wrong format"     → add timeUnit: "yearmonthdate" on temporal encoding
  "pie has too many slices"    → switch to bar
  "legend missing"             → add legend: {} to the color encoding
  "axis title wrong"           → fix the title property in the axis encoding
  "palette wrong"              → change palette to the correct vega-lite scheme name
  "threshold coloring missing" → set color_rules with the correct threshold and colors
  "should show distribution"   → change chart_type to boxplot or histogram
  "should show spread"         → change chart_type to boxplot or violin
  "scatter needs bucketing"    → SQL must GROUP BY ROUND(x/bucket) AS x_value, AVG(y) AS y_value
